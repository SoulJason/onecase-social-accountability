# OneCase — UX Walkthrough & Feedback Capture

Goal: experience the whole product like a real user, with fresh eyes, and
capture every reaction. Don't fix anything or hold back — rough notes are perfect.
The output of this is a prioritized revamp plan we build together.

## Before you start

- Have **two accounts** ready (e.g. `jason` and `tester`), already friends, with
  `tester` on the council of one of `jason`'s cases.
- Bonus: create **one brand-new third account** to feel the true cold start
  (empty everything). First impressions matter most and you only get them once.

## The four lenses (apply to every screen)

As you go, for anything that stands out, jot which lens it hits:

- 🤔 **Confusing** — I didn't know what to do / what this meant / where I was
- 🐢 **Friction** — too many taps, slow, awkward, keyboard/scroll annoyance
- ✨ **Delight** — this felt good (so we keep/expand it)
- 🕳️ **Missing** — I wanted to do X and couldn't / expected something that wasn't there
- 🎨 **Ugly** — looks/spacing/wording feels off

Format for notes: `[screen] — lens — what you felt`. Example:
`Home — Missing — I wanted to see how my friends are doing, not just my cases.`

## The walk (do it in this order)

### 1. Cold start (new 3rd account)
- [ ] Sign up. Note the very first screen you land on — is it obvious what to do?
- [ ] Did you know you needed a username? Was setting it discoverable?
- [ ] How did it feel to have nothing? Did the app help you take a first action?

### 2. Profile
- [ ] Open Profile (tap avatar). Set username + name.
- [ ] Anything you expected here that's missing (photo, bio, stats)?

### 3. Cases
- [ ] Create a case (emoji + color + title). Was the picker satisfying?
- [ ] Edit it (rename, recolor). Delete a throwaway one.
- [ ] On Home, is the list clear? Does a case tell you enough at a glance?

### 4. Tasks
- [ ] Open a case, add a couple of tasks.
- [ ] Tap ⋯ to edit one: rename, nudge progress, mark complete, delete.
- [ ] Was the ⏰ (clock-in) vs ⋯ (edit) distinction clear on the row?

### 5. Clock-in (the core — try EVERY path)
- [ ] Clock in, **cancel during the 10s grace**.
- [ ] Clock in (15s), let it **finish → success**, save progress.
- [ ] Clock in, **Give Up** mid-way.
- [ ] Clock in, **switch to another app** to trigger the leave-and-fail.
- [ ] How did each ending feel? Fair? Punchy enough? Confusing?

### 6. Friends
- [ ] From the other account, send a request; accept it on the first.
- [ ] Search, add, remove. Could you decline a request (you can't yet)?

### 7. Council
- [ ] Add a friend to a case's council.
- [ ] Sign in as that friend — find the shared case. Was it obvious it's shared?
- [ ] Could you tell what your friend is actually doing/progressing on?

### 8. Notifications
- [ ] Trigger each kind: friend request, accept, council add, and a clock-in
      fail/success on a shared case.
- [ ] Open the bell. Were the messages clear? Did you want to **tap** one to jump
      somewhere (you can't yet)?

### 9. Getting around (overall)
- [ ] How did you move between Home / Friends / Profile / Notifications? Did it
      feel like a real app, or like you were hunting for things?
- [ ] If you could add a bottom tab bar, what 3–4 tabs would you want?

## When you're done

Send me your notes in any form — a dumped list, voice-to-text, screenshots with
scribbles, whatever. I'll synthesize them (plus my own engineering notes) into a
ranked revamp plan: what to restructure, what to polish, what to add, in order.
